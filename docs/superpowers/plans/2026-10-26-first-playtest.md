# 首轮试玩反馈实施计划

> 使用 superpowers:subagent-driven-development 分工实现、逐项审查。用户已要求依次完成本轮修改。

**Goal:** 增加逐阶难度、改善击杀反馈和子弹可读性，让基础羁绊产生有元素依据的构筑行为。

**Architecture:** 继续使用静态 ES modules。难度、卡面解释和战斗反馈独立为小模块；战斗引擎是唯一结算来源，播放层只读取帧，不重复造成伤害。现有存档原位迁移。

**Tech Stack:** JavaScript、CSS、SVG 像素图形、Node 内置测试，GitHub Pages。

## 约束

- 保留 105 枚常驻子弹、五元素、现有子弹和羁绊 ID、三行四列弹夹、一夹一回合。
- 旧存档可继续；新难度和新怪群在新局生效，不能突改已经进行中的战斗难度。
- 怪物同一地面线可重叠；主画面不重新堆文字。
- 不降低 TLS 或修改电脑代理；本轮只修改游戏。
- 子弹图标用本地代码绘制的离散像素图形，避免增加在线资源依赖。
